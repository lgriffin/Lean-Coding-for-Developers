Decision:     API versioning strategy
Date:         2025-06-15
Status:       Decided
Trigger:      Partner X confirmed integration, starting July 1
Options:      URL path versioning (/v1/) with semver, header versioning,
              query param
Rationale:    URL path versioning with semver, simplest for partners to
              adopt, easiest to route at the gateway level. Semver gives
              partners a clear signal about breaking vs non-breaking changes.
              Header versioning considered, but partners said they prefer
              explicit URLs.
Constraints:  3 months of usage data showed /orders and /products are
              stable. /recommendations are still changing weekly — excluded
              from v1 contract.
Review date:  2025-12-01
