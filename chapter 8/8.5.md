# A3 Report: API Latency Incident 2026-02-12

## Background
API p99 latency spiked to 8s for 40 minutes following the 14:32 deploy.

## Current State
12,000 requests affected. 847 timeouts. 3 customer escalations.

## Goal
p99 latency stays below 200ms after every migration.

## Root Cause Analysis
5 Whys traced to a migration that added an index without running `ANALYZE`.
The query planner had no statistics for the new index and chose a full table
scan. Response time was 200x slower than expected.

## Countermeasures
| # | Action | Layer | Status |
|---|--------|-------|--------|
| 1 | Run `ANALYZE` on affected tables | Fix | Done |
| 2 | Add `ANALYZE` to migration template | Prevent (standard work) | This sprint |
| 3 | Add query plan assertion to CI | Detect (automated check) | Next sprint |

## Implementation Plan
- **#1** — @dbadmin — completed 2026-02-12
- **#2** — @platform-team — PR by end of sprint 14
- **#3** — @platform-team — spike in sprint 15

## Follow-up
Monitor p99 after each migration for 4 weeks. Alert if p99 exceeds 200ms
within 30 minutes of any deploy.

## Learnings
Index creation without a statistics update is a latent failure. The query
planner trusts stale stats and will choose a table scan over a new index
it does not know about.
